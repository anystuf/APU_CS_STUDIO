# Student-facing lesson and activity content

Use plain English suitable for Grades 11–12. Separate teacher planning notes
from student actions. A lesson has visible learning objectives and a collapsible
overview/schedule. Each activity appears once, under Required activities or
Extension activities, based on its stored required flag. Submitted means an
attempt was received, not that the student earned a passing grade.

Activity instructions support plain-text headings and numbered steps:

```text
## Learning goal
State what students will be able to do.

## Your task
Describe the problem and constraints in two or three sentences.

## Steps
1. Describe one action.
2. Describe the next action.

## Example
Include teacher-approved sample input/output. Never paste hidden test answers.

## Success criteria
1. Describe an observable requirement from the actual task.
2. Describe the explanation students must provide.

## Before you submit
State what students should run, check and submit.
```

These are authoring prompts, not automatic additions to existing assignments.
Keep existing requirements and grading expectations intact. The renderer treats
HTML and scripts as literal text. It also separates numbered instructions and
known lesson labels in older flattened descriptions without rewriting answers.
Bold emphasis (`**text**`), inline Python references (backticks), bullet lists,
links and fenced code examples render as formatted content, not raw punctuation.
Fenced examples preserve spaces, vertical bars and Python comments literally.
Do not delete `|` from registration examples: it is part of the input format.
Raw HTML is not enabled and unsafe link protocols are filtered by the renderer.
No accessibility certification is implied by the content template.
